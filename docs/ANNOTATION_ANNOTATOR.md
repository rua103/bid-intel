# 人工标注手册（标注员用）

> **这份是给标注员的。** 协调员的命令、脚本、流程都不在这里——**你不需要看那些**。
>
> **你不需要**：装环境、跑命令、懂后端、配 API Key。
> **你只需要**：一个浏览器，和耐心。

---

## 一、你要做什么（一句话）

打开一个网页，把 **6 条**政府采购公告的**正确信息**照原文填进去，导出文件交给协调员。

这 6 条会用来校准"什么算对、什么算错"的口径。**校准通过后还有 9 条正式任务给你。**

---

## 二、开工前，确认你拿到了两样东西

| | 是什么 | 谁给你 |
|---|---|---|
| ① | **一个 ZIP 文件**，名字是 `pilot-a.ready.zip` 或 `pilot-b.ready.zip` | 协调员 |
| ② | **一个网页链接**，形如 `http://192.168.x.x:5173/annotation.html` | 协调员 |

**两样都要有。** 缺任何一样就找协调员，不要自己想办法。

> **你是 A 还是 B？** 协调员会明确告诉你。
> **A 拿 pilot-a，B 拿 pilot-b。** 不要拿错，也不要看对方的答案——这是独立标注。

---

## 三、怎么操作（照做即可）

### 第 1 步：解压 ZIP

解压到一个固定文件夹，比如 `D:\标注任务\`。解压后应该看到：

```
pilot-a.bundle.json      ← 任务文件（必须留着）
sources\                 ← 原文附件文件夹（必须留着）
```

**两样都要留。** 只解压 json 是不够的——附件在里面。

### 第 2 步：打开网页

把协调员给你的链接粘进浏览器（Chrome 或 Edge）。

> 打不开？先确认你和协调员在**同一个网络**（同一个 WiFi 或同一个办公室网线）。

### 第 3 步：加载任务

点页面上这个按钮：

> **「载入我的标注任务」**

选中刚才解压出来的 `pilot-a.bundle.json`。

**加载成功的标志**：页面顶部显示任务名和**总条数（应该是 6）**。看不到数字就是没加载成功，重来一次。

### 第 4 步：逐条填写 ← 这是主要工作

页面**左边是原文，右边是表单**。

**每一条公告，重复这三件事：**

1. **看左边的原文**，必要时打开 `sources\` 文件夹里的附件对照
2. **在右边填**：
   - 七个字段：产品/服务名称、品目、品牌、规格型号、数量、单价、总价
   - 采购单位
   - 中标方（以及原文明确写出的中标金额）
   - 全部投标主体
3. **这一条全部填完**，才勾最下面那个勾选框：
   > **「本公告已对照原文：…」**

### 第 5 步：全部做完后导出

6 条全部勾完之后，点：

> **「导出已核验 Gold（6/6）」**

会下载一个文件，名字自动带 A 或 B（如 `annotator-a.gold.reviewed.json`）。

**直接把这个文件发给协调员。不要重命名。**

> ⚠️ 如果显示的是 `（4/6）`，说明还有 2 条没勾。**没做完导出的文件名里带 `.partial`，不能用于最终合并。**

---

## 四、填写规则（这部分最重要）

### 三条总原则

1. **原文没写 → 留空。** 不要猜，不要推理，不要"应该是"。
2. **页面上已有的内容不是答案。** 那是机器猜的，你**必须自己对照原文**。它猜对了也照样要核对。
3. **照抄原文的写法。** 公司名、品牌名原样记录，不要自己统一简称。

### 常见情况对照

| 你会遇到的情况 | 你应该怎么填 |
|---|---|
| 原文写品牌是「华为」 | 填 `华为` |
| 原文写「见附件」，但你翻遍附件也没找到 | **留空**（不是"没有"，是"没披露"） |
| 原文写「￥1472.6085 万元」 | 填 `14726085`（**换算成元**） |
| 原文写数量「2台」 | 数量填 `2`（**不要带"台"**） |
| 甲公司中标了 | 中标方列表填甲公司**，投标主体列表也要填甲公司** |
| 有几家公司投了标，但没写谁没中 | 投标结果选**「结果未披露」**，不要猜成"未中标" |
| 某公司没中标，原文明确写了 | 投标结果选「明确未中标」 |
| 「甲乙联合体」中标 | 就填 `甲乙联合体` **这一个**，不要拆成甲、乙两个 |
| 原文没分包 | 包号填 `default` |
| 附件打不开、是乱码、或看起来是验证码页 | **不要填，不要勾核验**，记下公告 ID 找协调员 |

### 绝对不要做的四件事

- ❌ 不要**猜**没写的东西
- ❌ 不要**照抄**机器预测
- ❌ 不要为了让两边"看起来对得上"而改答案
- ❌ 不要**重命名**导出的文件

---

## 五、什么时候**不能**勾核验

勾选框在下面这些情况下会**变灰点不动**（页面会告诉你原因）：

- 有标的行七个字段全空
- 采购包编号重复或为空
- 主体名字为空
- 数字填了非法内容（比如数量写成"2台"）

**看到红色提示就按提示改，改完再勾。**

> **改过任何内容，已经勾上的核验会自动取消。** 这是故意的——改了就要重新对照一遍。

---

## 六、中途要离开怎么办

页面会**自动保存**在当前浏览器里。但：

> **离开前一定要点「下载进度备份」。**

原因：自动保存只存在这台电脑的这个浏览器里。换电脑、清缓存、换浏览器配置，都会丢。

**恢复方式**：回到页面，还是点「载入我的标注任务」，选你下载的进度备份文件。

---

## 七、做完交给协调员什么

| 文件 | 什么时候 |
|---|---|
| `*.gold.reviewed.json`（6/6 导出） | 全部做完了 |
| 进度备份文件 | 如果中途要交接给别人 |

**就这些。** 不需要写报告，不需要解释。

---

## 八、遇到问题怎么办

| 情况 | 怎么办 |
|---|---|
| 网页打不开 | 确认和协调员在同一网络；截个图发给协调员 |
| ZIP 解压后没有 `sources\` | 找协调员重发 |
| 某条公告的附件打不开 / 是乱码 | **不要猜**，记下公告 ID 和采购包号，告诉协调员，这条跳过 |
| 不确定某个字段该不该填 | **先留空**，记下来问协调员 |
| 觉得原文和预测差太多 | 正常。**以原文为准** |
| 两条公告看起来是同一个项目 | 照实各填各的，告诉协调员你来问 |

**核心原则：拿不准就留空 + 问协调员。绝对不要猜。**
