# 数据质量与覆盖边界

## 数据来源

命题方提供的是 1038 条原始 HTML、压缩包及附件，不提供逐条 Gold 或 ground-truth。项目保存原始文件哈希、相对来源路径、解析文本、warning 和抽取证据，便于复核；这些元数据不能替代人工核验。

## 质量维度

- **来源完整性**：HTML/附件是否真实可读、哈希是否稳定、附件是否能唯一归属公告。
- **解析覆盖**：格式是否受支持、文本/表格/OCR 是否产生结果、是否存在跨页或嵌套表格。
- **字段披露**：原文没有披露的字段应保持 `null`；“见附件”不等于字段值。
- **实体口径**：采购单位、中标方、投标主体分角色保存；`unknown` 不能推断为 `nonwinner`。
- **包号一致性**：显式数字/字母包号可归一；名称型包号必须有标签和值的连续证据，无法确认时使用 `default` 并告警。
- **评测独立性**：调优 Gold、holdout Gold、predictions 和全量候选必须分开保存。

## 建议的抽样复核

人工质量复核应覆盖正文表格、附件表格、扫描/OCR、DOC/XLS、RAR/7z、多包、多中标人、无候选和异常下载响应。每条复核至少记录：公告 ID、包号、七字段、采购单位、全部投标主体、中标方/金额、来源证据、warning 和复核人。

24 条 `gold.merged.json` 是已经完成的调优/本地验证集；它不代表 1038 条分布。独立 holdout 的共同试标、裁决和正式分工完成前，不得运行最终路线评测，也不得把全量候选数、OCR覆盖率或入库成功数写成准确率。

## 可复现报告

抽取质量使用 [`EVALUATION.md`](EVALUATION.md) 中的字段、记录、实体和包号集合指标。附件覆盖和 warning 使用 `route_evaluation_report.py` 汇总；查询正确性使用 reviewed Gold 的独立 oracle，当前 SQLite/Neo4j 对照为 `6471/6471`，这只证明团队自建口径下查询实现一致，不证明官方答案正确。
