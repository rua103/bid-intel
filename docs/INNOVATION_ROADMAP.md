# 面向采购甲方的创新功能路线图

本文把可选创新点整理成可逐项实现和验收的路线。目标用户假设为采购监管、采购代理和审计人员：他们需要快速发现跨公告关系、理解系统依据、复核不确定结果并留下可追溯记录。

## 实施前的边界

- **holdout 标注优先并独立进行。** 两位标注员标注和裁决期间，不用 holdout 调 prompt、规则或归一化逻辑。
- **先冻结任务一抽取链路。** 创新功能通过独立分支开发；除非明确决定重做评测，不修改会改变候选结果的抽取、合并、包号和评测代码。
- **所有异常输出是核查线索，不是违法认定。** 不把共同投标、金额集中或关系密集直接称为围标、串标或腐败。
- **模型和图数据库都是实现手段。** 是否值得保留以可解释性、核查效率、运行稳定性和实测结果判断，不以技术名词数量判断。

## 建议顺序

### 1. 原文证据链与可解释抽取

**甲方价值：** 让审核人员知道每个字段和关系从哪里来，减少“系统说有，但无法复核”的情况。

**第一版范围：** 在公告详情中展示候选字段、来源公告和附件、页码/表格上下文、原文证据片段、包号、解析/OCR 警告及原始文件 SHA-256。对模型没有返回或系统没有保存的证据明确显示“无证据”，不事后编造引用。

**验收：** 随机抽取至少 20 条已有候选，七字段、采购单位、投标方和中标记录均能定位到具体来源；点击来源可打开正确文件或对应片段；缺失字段与“原文明确为空”可区分。若当前数据结构没有页码或字段级证据，先标示现有能力边界，不用猜测补齐。

**评测影响：** 只读展示现有来源证据，不改变抽取结果；不要在 holdout 标注过程中改标注员界面或任务材料格式。

### 2. 图谱关系风险线索

**甲方价值：** 从单条查询转向跨项目发现需要人工关注的关系模式。

**第一版范围：** 在现有五类查询之上增加少量可解释的图谱视图，例如供应商共同投标关系、跨项目重复合作、供应商中标/参与项目分布、采购单位与供应商的关系网络。每个节点/边显示计数口径、涉及公告和来源证据，并允许跳回公告复核。

**验收：** 每条线索展示可复算的构成公告、项目/包范围、时间窗口和规则说明；对 `default` 包号、OCR 告警、证据不足的记录作显式提示；使用合成案例验证预期关系和边界条件。界面文案使用“待核查线索”，不得直接判断违规。

**Neo4j 决策：** Neo4j 已支持五类分析 API；`/api/v1/graph` 当前使用 SQLite 投影。题目要求关系建模和查询，现有架构已满足核心查询；只有当图谱视图需要的跨跳分析或规模表现能证明 Neo4j 有实际收益时，才把可视化投影接入 Neo4j。若接入，保持 SQLite 默认/回退、数据集隔离和原响应结构，并提供等价性集成测试。

### 3. 人工复核队列

**甲方价值：** 把有限审核时间优先给高风险、低证据质量的记录。

**第一版范围：** 按明确可观察信号排序：缺字段、来源证据缺失、OCR 复核提示、包号为 `default`、跨附件候选冲突、金额/数量冲突和模型任务失败。每条队列项显示“为什么进入队列”；审核员可接受、修正、驳回并记录操作人和时间。

**验收：** 每个队列项能追溯触发规则；相同输入产生稳定排序；人工修改与机器原候选分开保存；修改后可查看前后差异和证据。若没有经过 Gold 校准的置信度，不显示伪精确的百分比，也不单凭模型自报置信度排序。

**前置条件：** holdout pilot 完成并固定标注说明后再改标注工作台，避免影响双人独立标注的一致性。

### 4. 模型治理、稳定性与成本台账

**甲方价值：** 能解释每批任务用了什么模型、花了多久、哪些失败、是否重试，以及失败时系统怎样处理。

**第一版范围：** 在任务级记录路线、模型 ID、配置摘要（不含密钥）、开始/结束时间、公告/附件请求数、耗时、token 用量（端点提供时）、失败分类、重试次数和最终回退路径。提供成功率、P50/P95 时长和 token 汇总。

**验收：** 用 mock 覆盖成功、超时、429、401/403、非法 JSON 和截断输出；日志和导出中不出现 API Key、Authorization 头或完整敏感请求体；重试不会重复入库；报告能区分“请求成功”和“抽取正确”。

**依赖：** 等赛事正式模型端点提供后，使用获准长样本再做真实链路验收；mock 和短 ping 不能替代该验收。

### 5. 公告和附件版本变更追踪

**甲方价值：** 识别更正公告、补充文件和成交结果变更，避免审核人员把不同版本混为一谈。

**第一版范围：** 支持导入同一公告的新快照，基于公告 ID、附件哈希和抓取时间识别版本；对正文和附件清单做结构化差异，突出采购包、供应商、金额、日期和七字段候选变化。每次导入保留旧版，不静默覆盖。

**验收：** 用人工构造的公告版本对照集验证新增、删除和修改；每个差异可定位到新旧原文；仅格式或空白变化不应造成大量语义变更；无法确认是否同一公告时提示人工匹配。

**前置条件：** 需要明确版本 ID、抓取时间和文件哈希的保存模型；官方材料若没有历史版本，只能用合成或之后实际收到的更正公告验证，不能宣称已回溯发现历史变化。

### 6. 本地化、隐私和离线应急

**甲方价值：** 让敏感采购材料尽可能留在指定环境，外部模型不可用时仍能继续核查。

**第一版范围：** 明确区分本地规则/OCR与外部模型调用；提供离线演示/处理模式、模型调用前提示、任务数据保留与导出清理说明，并给出出站请求审计记录。对不能联网或未获授权的环境禁用远程模型调用。

**验收：** 离线模式抓包/拦截测试证明不会请求模型端点；离线导入、五类查询和证据查看仍可用；日志不含密钥；清理演示数据不会删除原始归档或其他数据集。

### 7. 受控自然语言查询

**2026-10-07 实施状态：** 已增加只读 intent API、Pydantic 白名单校验、五场景执行路由、歧义/模型不可用回退和独立前端组件。当前使用本地 mock 验收；真实模型端点尚未验收，不宣称真实 NLP 准确率。时间/金额过滤在现有五类分析 API 尚未支持时会明确阻止执行，不静默改变查询口径。

**甲方价值：** 非技术人员可用自然语言访问现有分析能力，同时保留结果口径和审计性。

**第一版范围：** 只把用户问题映射到已定义的五类查询及有限参数，不生成任意 SQL/Cypher，不允许写操作。执行前展示识别出的场景、主体、时间/金额等过滤条件；有歧义时要求用户选择。结果同时展示口径说明、来源公告和实际分析后端。

**验收：** 建立至少 50 条问题的意图/参数测试集，覆盖同义表达、歧义、缺少主体、越权写请求和无关问题；所有输出只能调用白名单 API；模型不可用时可以手动选择原五类查询；报告测试准确率和拒答率，不将自然语言解释当证据。

## 建议的交付节奏

1. **当前：** 24 条本地 holdout Gold 已建立，第 1 项只读证据展示、第 2 项关系线索和第 7 项受控查询已接入；仍需保留 pilot-a 缺失、未形成完整双人一致性裁决的 Gold 质量边界。
2. **完成 Gold 质量确认、代码与提示冻结后：** 另行运行三路线最终评测，记录路线结论与剩余风险；当前已有运行仍不完整，本轮统一代码验收不启动该评测。
3. **评测结论稳定后：** 第 2 项和第 7 项首版已实现；优先推进第 3 → 4 项人工复核队列与模型台账，每项独立验收，现有功能的深化依据实测问题决定。
4. **时间充足时：** 按第 5 → 6 项推进版本差异与本地化治理；第 7 项另待官方端点下的真实自然语言验收。
5. 每项创新完成后更新演示脚本、测试证据和 [`GAP_ANALYSIS.md`](GAP_ANALYSIS.md)；只报告已经实现并实测的能力。

## 时间有限时的选择

优先补齐 **1 证据链的明确余项、2 已有图谱线索的可复核展示、3 人工复核队列**。第 4 项作为可靠性支撑；第 5–6 项可后续扩展，第 7 项保留已实现的受控查询并等待真实端点验收。

## 2026-10-07 实施记录：第 2 项首版

本轮已在现有五类查询/图投影基础上增加只读关系线索 API、独立前端面板与合成验证，覆盖共同投标、跨项目重复合作、参与/中标项目分布和采购单位—供应商网络摘要所需的证据字段。线索必须携带公告、项目、采购包、时间范围和可跳转的来源文件/定位；展示文案统一为“待核查线索”。

当前统计口径（2026-10-08 答疑迁移）：项目计数按 `projects.id` 去重；包计数按 `packages.id`；共同参与默认纳入 `winner`、`nonwinner`、`unknown`，`unknown` 显示为“结果未披露”；`include_winners=false` 只保留明确 `nonwinner`，不包含 `unknown`；`default` 包号保留并显示警告，不尝试猜测包名；OCR/附件解析失败、证据不足通过 `warnings` 原样提示；不显示未经校准的模型置信度。关系线索接口当前直接查询 SQLite，所有请求继续受 `X-Dataset-ID` 隔离；五类既有分析 API 的 Neo4j 选择和回退保持独立。首版曾默认仅 `nonwinner`，该历史默认值已由答疑迁移取代。

验证使用 `backend/tests/test_relationship_clues.py` 的纯合成数据（2 条公告、2 个项目、1 个 `default` 包、2 家重复合作供应商和 1 条 OCR 警告），不调用模型、不读取官方 Gold，也不产生 holdout 评测数据。实现时的合成契约测试为 3 passed（历史快照）；现有后端全量与前端测试/构建结果以本轮验收命令为准。线索接口尚无 Neo4j 实现，不宣称其已完成 Neo4j 等价性验收。
