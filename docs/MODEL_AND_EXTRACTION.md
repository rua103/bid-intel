# 模型与抽取路线

## 目标

赛题要求核心抽取使用 Qwen/DeepSeek 等允许的大模型能力。项目因此把模型放在正文、附件和非结构化字段的核心路径上；规则负责文档结构、确定性归一化、证据检查和离线兜底。`rules` 是基线，不是最终产品的路线声明。

## 三种路线

| 路线 | 模型调用 | 规则职责 | 用途 |
|---|---:|---|---|
| `rules` | 0 | 表格、别名、包号、数值和来源 | 可复现基线、离线演示、故障兜底 |
| `model` | 每个参与抽取文档至少一次 | schema、字段类型、证据和包号校验 | 模型能力对照 |
| `hybrid` | 按正文/附件调用 | 表格结构、确定性校验、安全合并 | 默认批处理路线 |

网页单条导入默认使用 `hybrid`；后台任务可显式选择三种模式，默认 `hybrid + OCR`。需要规则基线时必须明确传 `--mode rules`。没有模型配置时，规则路径仍可处理结构清晰的表格，但不能把这种降级路径写成模型评测结果。

## 模型输出契约

模型返回顶层 `metadata`、`participants`、`items`。每条标的包含产品/服务名称、品目、品牌、规格型号、数量、单价、总价七字段，以及 `package_code`、`source_evidence` 和可选的 `package_source_evidence`。主体包含采购包、结果状态、中标金额、来源证据和联合体成员。

模型不得根据常识补全原文没有披露的字段。`null` 表示来源未披露；“见附件”在附件没有对应证据时仍应为空。金额统一为人民币元，单位换算必须有原文依据。

## 证据和包号

模型输出通过 schema、字段类型和来源证据校验后才可进入合并流程。名称型包号还要求证据片段同时出现明确标签和值，例如：

```text
分包名称：教学仪器
```

只有“教学仪器”、项目标题、品目名或邻近段落时，`package_code` 必须回退 `default`。当前不使用“包名等于品目名”的推断，也不恢复宽松邻近文本正则。该限制已在 [`GAP_ANALYSIS.md`](GAP_ANALYSIS.md) 1.18/1.19 和定向回放报告中记录。

## 配置与验收

在 `backend/.env` 或网页“模型配置”面板设置 OpenAI-compatible `base_url`、模型名和 API Key。模型名应以允许的 `qwen` 或 `deepseek` 开头；真实比赛资源的版本、参数规模和来源必须另行留档，不能只写一个网关别名。

完整的端点切换、模型资源证明、mock 故障覆盖和长样本验收步骤见 [`MODEL_ENDPOINT_ACCEPTANCE.md`](MODEL_ENDPOINT_ACCEPTANCE.md)。

换模型端点时按顺序检查：

1. `POST /api/v1/model-config/test` 成功且没有把 Key 写入日志。
2. 一条短 HTML 返回合法 JSON，字段通过 schema。
3. 一条包含附件的公告能够分别记录每次请求、耗时、token 和 warning。
4. 人为触发或 mock 401、429、超时、截断 JSON，确认单公告可重试且不会写入失败结果。
5. 在调优 Gold 上比较三路线；代码和提示冻结后，再在独立 holdout 上运行 final。

## 质量解读

历史 24 条 HTML-only 调优评测显示 model 的字段代理分高于 rules，但完整记录和 hybrid 不能据此排序；6 条附件 pilot 也不能代表全部官方材料。模型是否最好必须以同一 holdout、同一包号边界、同一评测配置判断。所有模型实验报告必须同时给出失败请求、附件/OCR覆盖和成本遥测，避免把“请求成功”当成“抽取正确”。
