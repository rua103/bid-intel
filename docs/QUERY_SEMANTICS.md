# 数据模型与查询口径（待官方样例校准）

## 关系模型

- `organizations` 保存规范显示名；采购单位、中标方、投标方和产品供应商是关系角色，不是互斥的组织类型。
- `organization_aliases` 保存公告原名与来源。当前仅去空白、大小写归一；没有可靠证据时不把分公司、简称或相似名称合并。
- `projects` 保存公告/项目、采购单位、预算和公告成交总额；两种金额分列。
- `packages` 是频次统计的默认事件单位。没有包/标段信息时创建一个 `default` 包；拿到官方样例后再实现多包映射。
- `bid_participations` 保存主体的投标结果状态，包括 winner、nonwinner、unknown；unknown 不等于未中标。
- `awards` 单独保存每个包的中标供应商和可确认的供应商级中标金额。
- `procurement_items` 保存七项标的字段和来源文件、行号、原文证据。

## 五类查询的当前默认口径

1. 采购单位合作供应商：按中标供应商汇总不同采购包数和该供应商明确的中标金额；品牌单独显示为这些中标包中出现的品牌，不推断品牌与中标供应商是同一法律主体。金额先从 `awards` 汇总，再取标的物，避免一包多条明细导致金额重复。
2. 高频投标主体：按采购包数排序，默认包含中标方；协同投标组合按同一包共同出现的无序主体对统计。API 可通过 `include_winners=false` 查看仅非中标参与方的结果。
3. 中标供应商共同竞标者：查询基集为该供应商有 `awards` 记录的采购包；共同投标频次按不同采购包计，金额只归属有中标记录的主体。
4. 多家中标供应商的共同合作采购单位：采购单位需分别与每家所选供应商至少有一次中标关系，关系可以发生在不同包/项目；供应商级金额分开列出。
5. 多家供应商共同投标：要求所有所选主体出现在同一采购包（AND）；项目数按 distinct project 统计，包数另列，金额按该包唯一中标记录汇总。

## 需要用官方样例/基准确认的事项

- 官方按公告、项目还是采购包计算合作/竞标频次。
- 场景二和场景三中的“参与投标主体”是否包含中标方；赛题术语表把“投标参与方”专指未中标方。
- 场景三的历史范围是所选供应商中标的项目，还是所有参加投标的项目。
- 多包、多中标人、联合体、废标/撤回投标、重复/更正公告的处理方式。
- “项目金额/总金额”在各场景中对应预算、项目成交额、包成交额还是供应商级中标额。
- 品牌字段能否可靠映射到法律实体产品供应商。

题目现有文字不足以消除这些口径差异，所以不要把推测值写进正式基准结果。最终要以赛事提供的样例、字段说明和查询基准为准。
