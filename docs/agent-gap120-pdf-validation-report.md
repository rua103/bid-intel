根因：现有 PDF 解析会压平换行并加入 `[page:N]` 标记；用途模块只接受行首结构标题，页标记挡住历史标题。修复仅调整 `attachment_scope.py`：接受现有的正整数页标记及 `pdfplumber`/`ocr` 后缀；正文以合法页标记开头时，按标记恢复用途判定所需的页边界。只增加空白、不移除标记，确保候选证据偏移不变。PDF 解析输出、提示词与缓存键计算均未改动。

在当前生产 `_ingest_expanded` 中用真实 HTML/PDF 解析结果做一次 rules 入口回放，模型入口和外部网络被拦截、持久化入口替换为内存结果：目标 PDF 仍在 `source_files`，两类原有解析 warning 及带附件名的历史用途 warning 均保留，目标 PDF 标的/主体各为 0，模型请求和数据库写入各为 0。入口本身无需修改。9 条缓存候选的排除数 warning 在直接过滤回放中验证；rules 入口本来没有这 9 条模型候选，不能宣称该入口实际抽取再排除了 9 条。
