# 赛题答疑查询语义审计

核对材料：答疑表格第 3、5、9、10、11 条和赛题原文。本文记录迁移前问题；迁移后的实现和验证见 [`agent-query-semantics-migration-report.md`](agent-query-semantics-migration-report.md)。

## 结论

1. **产品供应商必须独立查询。** 答疑第 3 条明确“产品供应商就是任务一的品牌字段”，第 9 条要求场景一同时展示中标供应商和产品供应商的金额、合作次数。迁移后 `buyer_awardees` 增加 `product_suppliers`，返回项目/包频次、明确标的总价和逐条金额来源证据。
2. **答疑第 3 条说参与投标“中与不中都算”。** 已迁移：`buyer_bidders`、`supplier_co_bidders` 和关系线索默认包含 `winner`、`nonwinner`、`unknown`；`unknown` 仍不显示为未中标。旧 `6471/6471` 结果属于迁移前口径，需用新目录重跑 GAP 6a。
3. **资格性/符合性审查失败是否计参与没有正式答复。** 当前解析器把明确审查失败的主体记为 `nonwinner`，这符合“主体提交并参加过评审”的证据方向；若只有模糊审查文字，仍应保留 `unknown` 和原文证据，不能猜测。
4. **不同采购包是否构成同一项目的协同投标没有正式裁决。** 术语定义说协同投标是“同一或多个项目中共同参与投标”，因此答辩时应采用项目级关系，同时保留包级证据。当前五场景查询仍按同一 `package_id` 形成共同投标组合，项目级与包级口径需要在最终报告中明确，不能把旧 GAP 6a 数字当作答疑确认。
5. **第 5 条允许最细颗粒度，推定字段不作为准确率评测。** 当前抽取器不使用总价/数量反推单价或总价，避免推定值混入正式评测；如要展示推定能力，应单独标记 `inferred` 并排除出准确率字段。
6. **第 11 条租赁分类没有正式答复。** 不能依据“租赁”一词猜测货物/服务分类，只有原文明确品目或服务属性时才填写。

## 建议的后续动作

- 已同步 SQLite、Neo4j、关系线索和受控查询默认口径；冻结后重新生成 GAP 6a oracle。
- 产品供应商字段已增加；不复制中标供应商 award 金额。
- 在最终路线评测前冻结上述口径；评测报告中分别标出“官方答疑口径”和“团队历史 GAP 6a 口径”。
